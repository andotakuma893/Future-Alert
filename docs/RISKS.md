## 2. 終電情報で誤解させない仕組み（将来設計）

終電を逃すことはユーザーに大きな損害を与える。**「通知が来なかった」「間に合うと書いてあった」を理由に終電を逃す事態を防ぐ**ことを最優先にする。

1. **根拠の表示:** 終電の表示・通知には常に「データの種類（時刻表 / リアルタイム反映）」「提供元」「最終確認時刻」を添える。例: 「時刻表による終電 23:45（22:30時点）」。
2. **断定しない言い回し:** 「間に合います」ではなく「間に合う見込みです」。遅延データが無い路線では「遅延は反映していません」と明記する。
3. **安全マージン:** 目的地から駅までの所要時間に固定の余裕（例 +10分）を足して `notifyAt` を決める。余裕の値はユーザーに見える形にする。
4. **公式への導線:** 終電関連の通知・画面には必ず鉄道会社の公式運行情報へのリンクを付ける。
5. **データが古いときは警告に倒す:** 経路データの取得に失敗して古いままのときは、「最新の終電を確認できていません」という `warning` を出す（黙って古い値を使わない）。
6. **ダイヤ改正・特殊ダイヤ:** 休日・年末年始・臨時列車・ダイヤ改正日は、提供元が反映しているかを確認できるまで注意書きを出す。
7. **利用規約・免責:** 「参考情報であり、到着を保証しない」ことをオンボーディングと規約に明記する（文面は将来検討）。

## 3. 停止時のFallback（将来設計）

| 止まるもの | 起きること | Fallback |
|---|---|---|
| 監視エンジン | 通知が一切来ない | 外部の死活監視。エンジンが一定時間動いていないときは、アプリ画面に「現在、見守りが停止しています」と表示（アプリを開いたときに気づける） |
| 外部API（経路・天気・遅延） | Eventが更新されない | 取得失敗を記録し、古いデータで判断しない。重要なTrip中に長時間失敗した場合は `warning` で「最新情報を確認できていません」 |
| Pushサービス／購読失効 | 通知が届かない | 送信結果を記録し、アプリ画面に「最後に通知が届いた時刻」を表示。失効時は再購読を案内 |
| ユーザー端末（集中モード・電池切れ） | 通知が見えない | 防ぎきれない前提で、Trip作成時に「終電 ○時○分」を画面に大きく出し、通知だけに依存しない |

補足: 端末内で予約通知を出す仕組み（ネットに頼らず決まった時刻に通知）をPWAで使えるかは**未確認**。確認できれば、Trip作成時に「終電○分前」をローカル予約しておく二重化が有力。

## 4. パフォーマンスと `prefers-reduced-motion`

将来のUIで Glassmorphism（`backdrop-filter`）・パララックス・多数のアニメーションを使うと、iPhoneでのスクロールの引っかかりや電池消費につながる可能性がある（フェーズ0では実機計測していない）。

**提案: 将来のUI仕様に `prefers-reduced-motion` への対応を含めるべき。**

理由:
- iOSには「視差効果を減らす」系のアクセシビリティ設定があり、それを尊重するのはアクセシビリティ上の基本。
- 終電前など**急いでいる場面で使うアプリ**なので、アニメーションより情報の速さが優先される。
- 同時にパフォーマンス対策にもなる。

UI仕様に入れる内容の案:
1. `@media (prefers-reduced-motion: reduce)` でパララックス・大きな移動アニメーションを止め、フェード程度にする。
2. `backdrop-filter` は画面内の同時使用数を制限する（例: 固定ヘッダーとモーダルのみ）。
3. アニメーションは `transform` と `opacity` のみに限定する。
4. 通知タップから開く画面（Alert詳細）は**アニメーション無しで即表示**する。
5. フェーズ1で実機（古めのiPhoneを含む）でのフレームレートを確認する。
